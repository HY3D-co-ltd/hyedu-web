- 상태: **확정 (2026-11-17)**, 같은 날 Codex 리뷰 반영. 결정 사항은 §9, 공개 전 내부 시험은 §8, 화면 디자인은 §6.
- 구현: 공개본 `/contact` (2026-11-17 공개 → 보완을 위해 같은 날 내림, §9), 미리보기 `/ko/contact/preview/` (`src/components/contact-wizard/`, `src/lib/contact-wizard/`, `src/data/contact-wizard.ts`). 처리방침은 `/privacy` (`src/data/privacy-policy.ts`).
- 관련 문서: `docs/benchmark/2026-11-17-aigosu-inquiry-benchmark.md` §5.2 (처음 초안). 이 문서가 그 초안을 대체한다.
- 보내는 형식: 접수 엔드포인트의 **요청 계약 v1**. 이 문서는 계약의 필드 이름과 응답만 쓴다. 계약 원문과 수신 측 처리 규칙은 비공개 운영 문서에 있다.

## 1. 무엇을 근거로 짰나

처음 초안(벤치마크 §5.2)은 aigosu 구조에 우리 상품을 끼운 것이었다. 이번에는 **실제 상담 기록 40건**(전화·카톡·메일, 2025-06 ~ 2026-10)에서 운영자가 매번 되묻는 항목을 뽑아 질문을 고쳤다.

| 기록에서 반복된 것 | 질문에 반영한 곳 |
|---|---|
| 견적서·시행계획서(교육계획안)·제안서·사업자등록증을 거의 매번 요청한다 | S14 필요한 자료 |
| 크롬북·태블릿·노트북 보유 여부, 노트북 대여 요청 | S10 공간과 기기 |
| 체험부스는 운영자가 12개 항목 체크리스트(책걸상, 현수막, 기기, 보조 인력, 운영 시간, 점심, 강사 식사·생수, 와이파이, 전기·멀티탭, 숙소, 부스 크기, 장소)를 매번 다시 묻는다 | S11 부스 운영 조건 |
| 예산을 총액(부가세 포함 여부 포함) 또는 1인당 금액으로 말하고, 출처가 교육청 강사 예산·선도학교 사업비인 경우가 많다 | S13 예산 |
| 1·2순위 날짜와 시각(「16시 이후」, 「9:30–11:30」)까지 말한다. 다회기는 회기 수와 요일을 말한다 | S12 일정 |
| 「한 달 전 접수 원칙」, 「20명 기준 단가」를 상담 때마다 안내한다 | S12·S5 안내 문구 |
| 사이트 목록에 없는 프로그램(AI 웹툰, AI 음악, VR 해부학 등)이나 「새롭고 차별화된 프로그램 추천」을 요청한다 | S7 직접 입력·추천 요청 |
| 보조 인력을 더 붙이거나 통역이 함께하는 등 진행 방식을 따로 상의한다 | S4 진행에 상의할 점 |
| 한양대 ERICA로 학생이 방문하는 형태(체험·캠프)를 문의한다 | S8 장소 |
| 「16:20 퇴근이라 그 전에 연락」, 「오전 수업이라 전화 불가」 | S15 통화 편한 시간 |
| 학교장터·나라장터·세금계산서로 결제할 수 있는지 묻는다 | S14 구매 방법 |
| 학부모가 자녀 개인 캠프 참가를 문의한다 | S1 개인 참가 분기 |

## 2. 흐름 한눈에

한 화면에 질문 하나를 둔다. 진행 표시는 질문 수가 아니라 네 단계로 보여 준다(분기마다 질문 수가 달라서).

```
[교육 정보]           [대상·장소·일정]                        [예산·요청]        [연락처]
S1 교육 형태 ─┬─ 개인 참가 → 네이버 예약 안내 (접수 없이 끝)
              └─ S2 기관 → S3 수업 시간* → S4 대상 → S5 인원 → S6 분야* → S7 프로그램
                 → S8 장소 → S9 지역* → S10 공간·기기* / S11 부스 조건* → S12 일정
                 → S13 예산 → S14 자료·요청 → S15 연락처·동의 → 제출 → 완료 화면
                                                         (* 조건이 맞을 때만 나온다)
```

교육 형태(S1)에 따라 나오는 질문:

| 질문 | 체험교실 | 동아리 | 특강 | 체험부스 | 단체 캠프 | 온라인 | 모르겠어요 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| S3 수업 시간 (학교만) | ✓ | ✓ | ✓ | | | | ✓ |
| S6 분야 | ✓ | ✓ | | | | | ✓ |
| S7 프로그램 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| S11 부스 조건 | | | | ✓ | | | |

진행 장소(S8)에 따라 나오는 질문. 교육 형태와 상관없이 이 표가 정한다.

| S8 답 | S9 지역 | S10 공간 묶음 | S10 기기 묶음 |
|---|:-:|:-:|:-:|
| 우리 기관으로 와 주세요 · 다른 장소 | ✓ | ✓ | ✓ |
| 한양대 ERICA 캠퍼스로 갈게요 | | | |
| 온라인 실시간 | | | ✓ |
| 녹화 영상 | | | |
| 아직 모르겠어요 | | ✓ | ✓ |

- 단, 체험부스는 S10 대신 S11을 보여 준다.
- 화면 수는 대략 11~14개다.

**공통 규칙**

- 모든 질문 아래에 「왜 여쭤보나요」 한 줄을 둔다(각 질문의 *왜* 칸이 화면 문구다).
- S2와 S15를 뺀 모든 질문에 **「아직 모르겠어요」**(또는 「건너뛰기」)가 있다. 필수 답은 S1, S2, S15뿐이다.
- **추가 입력이 없는 하나 고르기만 누르는 즉시 다음으로 넘어간다.** 여러 개 고르기, 직접 입력, 같은 화면의 보충 항목(S2 기타, S8 캠프 기간, S12 날짜·시간, S13 금액 등)이 있는 화면은 「다음」 버튼으로 넘어간다.
- 「모르겠어요」와 「건너뛰기」도 답이다. 보낼 때 빈칸으로 버리지 않고 `미정`으로 보낸다(§4).
- 화면에 보이는 말은 ko/en 두 벌을 둔다. **보내는 값은 언어와 상관없이 한국어 기준값**이다(운영자가 한국어로 읽기 때문).

## 3. 질문 상세

`→` 표시는 그 답이 들어가는 계약 v1 필드다. 문자열 조립 규칙은 §4에 있다.

### S1. 어떤 교육을 찾으세요? (What kind of program are you looking for?)

*왜*: 교육 형태에 따라 견적 기준과 다음 질문이 달라져요.
형식: 하나 고르기 (타일, 작은 설명 포함). `→ inquiry.eduType`

| 보기 | 작은 설명 | 보내는 값 |
|---|---|---|
| 찾아가는 체험교실 | 강사가 찾아가는 1회 체험 수업 (2~4교시) | `찾아가는 체험교실` |
| 동아리 · 여러 회차 수업 | 같은 학생들과 2회 이상 이어서 하는 수업 | `동아리` |
| 전문인 특강 | 강연 · 진로 특강 | `특강` |
| 체험 부스 | 축제 · 박람회 · 학교 행사 부스 운영 | `체험부스` |
| 단체 캠프 | 하루 ~ 2박 3일 캠프 | `오프라인캠프` (S8에서 「온라인 실시간」을 고르면 `온라인캠프`) |
| 온라인 교육 | 실시간 화상 · 녹화 영상 수업 | `온라인체험` |
| 자녀(개인) 참가 신청 | 토요캠프 · 경진대회 대비반 · 방학 캠프 | 접수하지 않고 개인 참가 안내로 이동 (§5.5) |
| 아직 모르겠어요 | 상담하면서 정할게요 | `null` |

### S2. 어디에서 문의하시나요? (Where are you contacting us from?)

*왜*: 학교인지 기관인지에 따라 학년 보기와 수업 시간이 달라져요.
형식: 하나 고르기. 「기타」는 직접 입력(40자). `→ org.type`

초등학교 / 중학교 / 고등학교 / 특수학교 / 대학교 / 교육청 · 공공기관 · 지자체 / 청소년수련관 · 도서관 · 복지관 / 학원 · 교육업체 / 기업 · 행사 대행사 / 기타(직접 입력)

### S3. 어느 시간에 하는 수업인가요? (Which school time slot is this for?)

조건: S2가 초·중·고·특수학교이고 S1이 체험교실 · 동아리 · 특강 · 모르겠어요일 때.
*왜*: 정규 수업인지 방과후인지에 따라 교시 길이와 진행 방식이 달라져요.
형식: 하나 고르기. `→ inquiry.mode` (뒷부분)

정규 수업(교과 · 창체) / 자유학기 · 진로 활동 / 방과후 · 늘봄 / 동아리 시간 / 교사 연수 / 학교 행사 · 축제 / 아직 모르겠어요

- 「교사 연수」를 고르면 S4에서 「교사」를 미리 골라 둔다.

### S4. 누가 참여하나요? (Who will take part?)

*왜*: 학년에 맞는 프로그램만 골라서 보여 드릴게요.
형식: 여러 개 고르기 + 아래에 「진행에 상의할 점」 체크(선택). `→ inquiry.audience`

| S2 답 | 보기 |
|---|---|
| 초등학교 | 1학년 ~ 6학년, 교사 |
| 중학교 · 고등학교 | 1학년 ~ 3학년, 교사 |
| 특수학교 | 초등부, 중등부, 고등부, 전공과, 교사 |
| 그 밖 | 유아, 초등 저학년(1~3), 초등 고학년(4~6), 중학생, 고등학생, 대학생 · 성인, 교사, 가족(보호자 동반) |

진행에 상의할 점 (선택, 여러 개): 보조 인력 등 진행 지원을 상의하고 싶어요 / 통역이나 쉬운 한국어 진행이 필요해요

- 프로그램 필터용 대응: 초등 학년 · 초등부 · 초등 저/고학년 → `elementary`, 중 → `middle`, 고 → `high`, 대학생 · 성인 · 교사 → `adult`. 유아와 가족은 필터를 걸지 않는다.
- 「진행에 상의할 점」은 **필요한 지원**만 묻고, 학생의 장애 · 출신 같은 사유는 묻지 않는다. 화면에 「학생 개인에 대한 정보는 적지 말아 주세요」를 적는다.

### S5. 몇 명 정도인가요? (How many participants?)

*왜*: 강사 수와 재료 준비량이 인원으로 정해져요.
형식: 숫자 입력(명) + 학급(반) 수(선택) + 「아직 미정(모집 예정)」 버튼. `→ inquiry.audience`

- 체험부스면 질문을 「부스를 체험할 전체 인원은요?」로 바꾼다.
- 체험교실 · 동아리에서 20 미만을 넣으면 안내: 「체험교실은 20명 기준 단가예요. 20명보다 적으면 1인 금액이 달라질 수 있어요.」(막지는 않는다.)

### S6. 관심 있는 분야는요? (Which fields interest you?)

조건: S1이 체험교실 · 동아리 · 모르겠어요일 때.
*왜*: 고르신 분야의 프로그램을 먼저 보여 드릴게요.
형식: 여러 개 고르기. S7 필터에 쓰고, 프로그램을 안 고르면 S7 조립에 쓴다.

AI 인공지능(`ai`) / 코딩 · 로봇(`coding`) / 메이커: 3D · 드론 · VR(`maker`) / STEAM · 과학(`steam`) / 추천해 주세요

### S7. 관심 있는 프로그램을 골라 주세요 (Pick the programs you're interested in)

*왜*: 고르신 프로그램으로 견적과 교육계획안을 바로 준비할게요.
형식: 썸네일 카드 여러 개 고르기 + 「목록에 없는 프로그램」 직접 입력(100자) + 「추천해 주세요」 토글. 건너뛸 수 있다. `→ inquiry.interestPrograms`

| S1 답 | 보여 줄 목록 (`src/data`) | 필터 | 카드의 가격 줄 |
|---|---|---|---|
| 찾아가는 체험교실 · 모르겠어요 | `programs.ts` | 분야(S6) × 대상(S4) | `price` |
| 동아리 | `youth-clubs.ts` + `programs.ts` 중 `clubAvailable` | 분야(S6) × 대상(S4) | `price` |
| 특강 | `special-lectures.ts` | 없음 | `price` |
| 체험부스 | `booths.ts` | 없음 | 「견적 문의」 (가격 필드 없음) |
| 단체 캠프 | `camps.ts` | 대상(S4) | `price` |
| 온라인 | `online-courses.ts` | 없음 | 「실시간 ○원 / 영상 ○원」 (`priceLive` · `priceVideo` 중 있는 것) + 가능한 방식 표시 |

- **`hidden: true`인 프로그램은 어디에서도 쓰지 않는다**(목록, 미리 채우기, 추천 모두).
- 동아리 목록에서 제목이 같은 항목(예: 「자율주행자동차 엔지니어」)은 하나만 보여 준다. `youth-clubs.ts` 쪽을 남긴다(회기 단가가 그쪽에 있다).
- 거른 결과가 0개면 분야 필터부터 풀고, 그래도 0개면 대상 필터도 풀어 전체를 보여 준다. 이때 「조건에 딱 맞는 프로그램이 없어 비슷한 프로그램을 보여 드려요」를 띄운다.
- 보내는 값은 `title`(한국어)이다.

### S8. 어디서 진행하나요? (Where will it take place?)

*왜*: 장소에 따라 출장비와 준비물이 달라져요.
형식: 하나 고르기. 캠프면 같은 화면에 기간(당일 / 1박 2일 / 2박 3일 / 미정)을 함께 고른다. `→ inquiry.mode` (앞부분)

| 보기 | 체험교실 | 동아리 | 특강 | 부스 | 캠프 | 온라인 | 모르겠어요 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| 우리 기관(학교)으로 와 주세요 | ✓ | ✓ | ✓ | ✓ | ✓ | | ✓ |
| 한양대 ERICA 캠퍼스로 갈게요 | ✓ | ✓ | ✓ | | ✓ | | ✓ |
| 다른 장소(연수원 · 행사장 · 야외) | | | ✓ | ✓ | ✓ | | ✓ |
| 온라인 실시간 | | ✓ | ✓ | | ✓ | ✓ | ✓ |
| 녹화 영상 | | | | | | ✓ | |
| 아직 모르겠어요 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

- ERICA 방문형은 표대로 체험교실 · 동아리 · 특강 · 캠프에서 받는다(2026-11-17 결정).
- 온라인 과정마다 가능한 방식이 다르다(예: 영상만, 실시간만). 고른 방식을 지원하지 않는 과정이 S7에 있으면 그 과정 이름 옆에 「영상만 가능」처럼 알려 준다. 막지는 않고 그대로 보낸다(상담에서 조정).

### S9. 교육 장소는 어디인가요? (Where is the venue?)

조건: §2의 「진행 장소에 따라」 표.
*왜*: 강사 배정과 출장비 계산에 필요해요.
형식: 시 · 도 선택(17개) + 시 · 군 · 구 입력(선택) + 장소 이름(선택, 예: 체육관 · ○○연수원). `→ inquiry.venue` (앞부분)

- 상세 주소는 받지 않는다. 계약 단계에서 받으면 된다.

### S10. 교육 공간과 기기를 알려 주세요 (Tell us about the room and devices)

조건: §2의 「진행 장소에 따라」 표. 체험부스는 S11로 대신한다.
*왜*: 수업에 따라 1인 1기기가 필요해요. 부족하면 저희가 준비해 가요.
형식: 묶음 두 개, 여러 개 고르기. `→ inquiry.venue`

- 공간: 일반 교실 / 컴퓨터실 / 강당 · 체육관 / 야외
- 기기: 빔프로젝터 · 스크린 / 학생 1인 1대 PC · 노트북 / 크롬북 / 태블릿 / 와이파이 / 기기가 없어요(대여 필요)
- 아직 모르겠어요

### S11. 부스 운영 조건을 알려 주세요 (Booth conditions)

조건: S1이 체험부스일 때.
*왜*: 행사 부스는 현장 조건에 따라 준비가 크게 달라져서 미리 여쭤요.
형식: 한 화면에 묶음 여러 개. **모두 선택 입력**이다. 일부만 채워도 「다음」으로 넘어가고, 하나도 안 채우면 「건너뛰기」로 넘어간다(2026-11-17 결정: 항목은 유지하되 필수로 하지 않는다). `→ inquiry.venue`, `inquiry.schedule`, `inquiry.extra`

| 묶음 | 형식 | 보기 |
|---|---|---|
| 부스 수 | 숫자 | (미정 가능) |
| 운영 시간 | 시작 ~ 끝 시각, 점심시간 포함 여부 | → schedule |
| 장소 | 하나 | 실내(교실 · 강당 · 체육관) / 실외(운동장 · 공원) |
| 부스 크기 | 짧은 입력 | 예: 3m × 2m |
| 현장에서 지원 가능한 것 | 여러 개 | 책걸상 · 테이블 / 전기 콘센트 / 멀티탭 / 와이파이 / 노트북 · 태블릿 / 운영 보조 인력 / 강사 식사 / 생수 / 숙소(지방 · 이른 시작) |
| 저희에게 필요한 것 | 여러 개 | 현수막 · X배너 제작 / 보조 강사 추가 → extra |

운영자 체크리스트 12개 중 「총 참가 인원과 연령대」(S4·S5)와 「진행 장소 주소」(S9)는 앞 질문에서 이미 받는다.

### S12. 언제 하실 계획인가요? (When are you planning it?)

*왜*: 강사 일정은 보통 한 달 전에 정해져요. 날짜가 가까우면 먼저 연락드릴게요.
형식: 세 갈래 중 하나 + 교육 형태별 보충. `→ inquiry.schedule`

- **날짜가 정해졌어요** → 날짜 최대 3개(1 · 2 · 3순위) + 시간대: 오전 / 오후 / 방과후(16시 이후) / 종일 / 직접 입력(시각)
- **대략적인 시기만 있어요** → 이번 달 / 다음 달 / 이번 학기 / 다음 학기 / 방학 중 / 직접 입력
- **아직 모르겠어요**

| S1 답 | 보충 |
|---|---|
| 체험교실 · 특강 | 교시 수 1 / 2 / 3 / 4 이상, 1교시 길이 40 · 45 · 50분 / 모름 |
| 동아리 | 회기 수 2~3 / 4~6 / 7~12 / 13회 이상 / 미정, 회기당 교시 수, 요일(여러 개) |
| 체험부스 | 행사 일수 1일 / 2일 이상 (운영 시간은 S11) |
| 단체 캠프 | 없음 (기간은 S8) |

- 가장 빠른 날짜가 30일 이내면 안내: 「한 달이 안 남은 일정이에요. 접수하시면 가능 여부부터 바로 확인해 드릴게요.」 그리고 `extra` 맨 앞에 `[한 달 이내 일정]`을 붙인다(알림 메일에서 눈에 띄게).

### S13. 예산은 어느 정도인가요? (What's your budget?)

*왜*: 예산에 맞춰 프로그램과 인원 구성을 제안해 드릴게요.
형식: 하나 고르기 + 금액 입력 + 출처(선택). `→ inquiry.budget`

- **총액이 있어요** → 금액(만 원) + 부가세: 포함 / 별도 / 모름
- **1인당 기준이 있어요** → 금액(원)
- **견적을 먼저 받고 싶어요**
- 예산 출처(선택): 학교 · 기관 운영비 / 교육청 · 지자체 지원 사업 / 선도학교 · 중점학교 사업비 / 수익자(학부모) 부담 / 기업 예산 / 모르겠어요

### S14. 필요한 자료와 더 하실 말씀 (Documents you need, anything else)

*왜*: 필요한 서류를 미리 알려 주시면 첫 회신에 같이 보내 드릴게요.
형식: 여러 개 고르기 + 하나 고르기 + 자유 입력. `→ inquiry.extra`

- 필요한 자료: 견적서 / 교육계획안(시행계획서) / 제안서 / 커리큘럼 · 수업 예시 자료 / 사업자등록증 · 통장 사본
- 구매 방법(선택): 학교장터(S2B) / 나라장터 / 세금계산서 발행 후 계좌이체 / 카드 결제 / 모르겠어요
- 자유 입력(600자): 「예) 결과물을 학생들이 가져갈 수 있으면 좋겠어요. 작년에 한 블루투스 스피커를 다시 하고 싶어요.」 아래에 「학생 이름이나 건강 정보 같은 개인정보는 적지 말아 주세요」를 적는다.

### S15. 회신받으실 연락처 (How should we reach you?)

*왜*: 접수 내용을 확인한 담당자가 평일 9~18시에 연락드려요.
형식: 입력 폼. `→ org.name`, `contact.*`, `consent`

| 칸 | 필수 | 규칙 | 계약 필드 |
|---|:-:|---|---|
| 기관명 | ✓ | 80자 | `org.name` |
| 담당자 성함 | ✓ | 40자 | `contact.name` |
| 휴대폰 | ✓ | `01[016789]` + 7~8자리, 하이픈 자동 | `contact.mobile` |
| 이메일 | 회신 방법이 이메일이면 ✓ | 120자, 형식 검사 | `contact.email` |
| 학교 · 기관 전화 | | 20자 | `contact.phone` |
| 회신 방법 | | 전화 / 문자 / 이메일 / 카카오톡 (하나) | `contact.replyPreference`, `inquiry.extra` |
| 통화 편한 시간 | | 오전 / 점심 / 오후 / 16시 이후 / 언제든 | `inquiry.extra` |
| 개인정보 수집 · 이용 동의 | ✓ | 체크박스 + 고지 + 처리방침 링크 | `consent.privacy`, `consent.version` |

- **카카오톡은 고객이 먼저 말을 걸어야 대화가 열린다.** 카카오톡을 고르면 안내: 「접수 후 카카오톡 채널 '한양미래연구소'에 접수번호를 보내 주세요. 그 채팅으로 답변드릴게요.」 완료 화면에 [접수번호 복사]와 [채널 채팅 열기] 버튼을 둔다.
- 동의 고지 문구는 처리방침 초안(`2026-11-17-privacy-policy-draft.md` 부록 A)을 그대로 쓴다.
- `autocomplete`: `organization`, `name`, `tel`, `email`. 휴대폰 `inputMode="tel"`.
- 보이지 않는 허니팟 칸(`hp`)을 둔다.

## 4. 계약 v1로 조립하는 규칙

답은 아래처럼 문자열로 묶어 보낸다. 조각은 ` · `로 잇는다. 수신 측은 문자열 하나당 1000자, 배열 항목 하나당 100자에서 자른다.

**빈 상담내용을 만들지 않는다.** 수신 측은 `inquiry`의 여섯 필드(관심 프로그램, 일정, 대상, 예산, 진행 방식, 장소)와 `extra`로 상담내용을 만들고, 상담내용이 비면 운영 목록에 올리지 않는다. 그래서 다음 규칙을 둔다.

- 화면에 나왔는데 「모르겠어요」나 「건너뛰기」로 넘어간 질문은 그 필드에 `미정`을 넣는다.
- 화면에 나오지 않은 질문의 필드는 비운다.
- S12 일정과 S13 예산은 모든 경로에서 나오므로, 어떤 접수든 상담내용이 적어도 두 줄은 생긴다.

| 필드 | 조립 |
|---|---|
| `inquiry.eduType` | S1 값. 모르겠어요면 `null` |
| `inquiry.interestPrograms` | S7에서 고른 제목들 + 직접 입력 + (추천 토글이면) `추천 요청(분야: AI 인공지능, 코딩 · 로봇)`. 아무것도 안 골랐는데 S6 분야가 있으면 추천 항목 하나만 넣는다. S7을 건너뛰고 S6도 없으면 `["미정"]` |
| `inquiry.schedule` | 날짜·시기 · 시간대 · 교시/회기/요일 · (부스) 운영 시간·일수 · (캠프) 기간. 예: `1순위 2026-12-15(화), 2순위 12-14(월) · 오전 · 3교시(50분)` |
| `inquiry.audience` | 대상 · 인원 · 학급 수 · 진행에 상의할 점. 예: `초등 4~6학년 · 약 60명(3개 반) · 진행 지원 상의 필요` |
| `inquiry.budget` | 예: `총 300만 원(부가세 포함) · 교육청 · 지자체 지원 사업` / `1인당 30,000원` / `견적 먼저 요청` |
| `inquiry.mode` | S8 장소 · S3 수업 시간. 예: `우리 기관 방문 · 방과후 · 늘봄` |
| `inquiry.venue` | S9 지역·장소 이름 · S10 공간·기기 · S11 장소·크기·부스 수·지원 가능한 것 |
| `inquiry.extra` | 줄 단위: `[한 달 이내 일정]` / `필요 자료: …` / `구매 방법: …` / `부스 요청: …` / `회신 방법: …` / `통화 편한 시간: …` / 빈 줄 / 자유 입력. 합쳐서 1000자 안. 회신 방법은 `contact.replyPreference`로도 가지만 그 칸은 원본 테이블에만 남아, 실무자가 보는 상담내용과 알림 메일에 실으려고 여기에도 적는다 (2026-11-17) |
| `inquiry.answers` | 화면에 나온 모든 질문의 `{q: 한국어 질문, a: 한국어 답}`. 「모르겠어요」도 그대로 넣는다. 연락처(S15)는 넣지 않는다 |
| `source.page` / `source.program` | 현재 경로(`/ko/contact/`), 진입 파라미터의 slug |

## 5. 화면 동작

### 5.1 진입과 미리 채우기

| 진입 | 동작 |
|---|---|
| `/contact/` | S1부터 |
| `/contact/?program=<slug>` (프로그램 상세 페이지의 신청 버튼) | `programs.ts`에서 찾고 `hidden`이 아니면 S1=체험교실, S6=그 분야, S7=그 프로그램으로 채우고 S2부터 보여 준다. 채운 답도 요약에서 고칠 수 있다. `source.program`=slug |
| `/contact/?type=club\|lecture\|booth\|camp\|online` (서비스 목록 페이지 버튼) | S1만 채운다 |
| 목록에 없거나 숨김인 slug, 모르는 type | 무시하고 S1부터 |

- 정적 export라 서버가 쿼리를 읽을 수 없다. 쿼리는 클라이언트에서 읽는다(`useSearchParams`를 쓰면 `Suspense` 경계 안에 둔다).
- 동아리 · 캠프 등은 지금 상세 페이지가 없어 `type`만 쓴다. `youth-clubs.ts`와 `programs.ts`의 slug가 겹치므로(`3d-pen-designer`) `program`은 `programs.ts` 전용으로 둔다.
- 지금 프로그램 상세 페이지의 신청 버튼은 파라미터 없이 `/contact`로 간다. 파라미터를 붙이는 일은 공개 때 한다(§8).

### 5.2 요약 패널과 되돌아가기

- 데스크톱(lg 이상): 오른쪽에 「적어 주신 내용」 패널. 항목을 누르면 그 질문으로 돌아간다. 돌아가서 답을 바꾸면 조건이 달라진 뒤쪽 질문의 답은 지운다.
- 모바일: 하단 고정 바에 「적어 주신 내용 (n)」 버튼 → 아래에서 올라오는 시트.

### 5.3 임시 저장

- 키: 공개본 `hyedu:contact-draft:v1`, 미리보기 `hyedu:contact-preview-draft:v1`(섞이지 않게 나눈다).
- **저장하는 답은 허용 목록으로 정한다.** 보기 중에서 고르는 답(S1~S13, S14 필요한 자료 · 구매 방법)만 저장한다. 다음은 저장하지 않는다.
  - S14 자유 입력
  - S15 전부
  - 미리보기 의견
  - 학교 교무실 공용 PC를 고려한 결정이다.
- 저장할 때 시각을 함께 남기고, 들어왔을 때 7일이 지났으면 지운다. `localStorage`에는 스스로 지워지는 기능이 없으므로, 처리방침에는 「7일이 지난 초안은 다음 접속 때 지운다」고 적는다.
- 다시 들어오면 「작성하던 내용이 있어요. 이어서 하시겠어요?」
- 접수에 성공하면 지운다. 저장소를 못 쓰는 환경(사생활 보호 모드 등)에서는 저장 없이 그대로 동작한다.

### 5.4 제출과 응답

**보내는 곳**

- 환경 변수 `NEXT_PUBLIC_INQUIRY_ENDPOINT`. `NEXT_PUBLIC_*`는 빌드할 때 고정되므로 배포 워크플로(`.github/workflows/deploy.yml`)의 빌드 단계에 저장소 변수로 넣는다. 값은 브라우저 코드에 그대로 드러나므로 비밀값이 아니다.
- 값이 없을 때:
  - 미리보기는 「보내지 않는 시험 모드」로 동작한다(§8).
  - 공개본에서 위저드를 켠 뒤로는 값이 없으면 빌드를 실패시킨다. 손님이 보는 화면에서 접수가 조용히 안 되는 일을 막기 위해서다.
- 기본은 `Content-Type: application/json`이다. 중계 시험에서 CORS 사전 요청이 막히면 `text/plain;charset=UTF-8`로 바꾼다(수신 측은 문자열 본문도 읽는다).
- 클라이언트도 수신 측과 같은 규칙으로 먼저 검사한다(필수 칸, 휴대폰 형식, 길이).

**제출 번호와 다시 보내기**

- `submissionId`는 「제출」을 누를 때 `crypto.randomUUID()`로 만들고, 그때의 답을 **제출 묶음으로 고정**한다.
- 같은 `submissionId`로 다시 보내는 것은 **고정된 그 묶음 그대로**일 때만이다. 수신 측은 같은 번호로 여러 번 들어오면 가장 먼저 들어온 것 하나만 처리한다.
- 결과를 모르는 상태(네트워크 오류 · 시간 초과)에서 고객이 답을 고치면 새 `submissionId`로 새 묶음을 만든다. 첫 묶음이 이미 저장됐다면 운영 목록에 두 건이 생길 수 있다. 고친 내용을 잃는 것보다 낫다.

**응답 처리**

| 응답 | 화면 |
|---|---|
| 200이고 `receipt`가 형식에 맞음 (공개본 `261117-001`, 미리보기 `T-261117-001` — 접수일 + 그날 순번 3자리. 2026-11-17 전에는 `W-`/`T-` + 제출ID 앞 8자리였다) | 완료 화면(§5.6) |
| 400 `{reason:"invalid", errors}`이고 `errors`에 화면 칸이 있음 | 첫 칸이 있는 질문으로 돌아가 표시. 입력은 그대로 둔다 |
| 400인데 `errors`가 비었거나 화면 칸이 아님(`schema`, `submissionId`) | 일반 오류 화면 |
| 500 `{reason:"save_failed"}` (502가 아니다 — n8n Cloud 앞단이 502를 자기 HTML 오류 페이지로 바꾸고 CORS 헤더를 떨어뜨린다) | 「접수 저장에 실패했어요. 적어 주신 내용은 그대로 있어요.」 + [다시 보내기] [내용 복사] [카카오톡으로 문의] [전화 070-8064-0829] |

| 그 밖(200인데 `receipt` 없음, JSON이 아님, 모르는 상태 코드) | 일반 오류 화면 |

## 8. 공개 전 내부 시험 (미리보기)

대표와 실무자가 직접 눌러 보고 의견을 낸 뒤에 공개한다. 그동안 지금 `/contact`는 그대로 둔다.

**미리보기 경로: 같은 사이트의 숨은 주소 `/ko/contact/preview/`**

- `noindex, nofollow`를 걸고 사이트맵 · 메뉴 · 다른 페이지 링크에 넣지 않는다.
- **이것은 접근 통제가 아니다.** 주소를 알면 누구나 열 수 있고, 시험 접수도 외부 저장소에 실제로 저장된다. 그래서 다음을 지킨다.
  - 시험하는 분께 **실제 개인정보 대신 시험용 값**을 쓰도록 안내한다.
  - 미리보기의 S15에 [시험용 연락처 채우기] 버튼을 둔다(기관명 「시험 기관」, 성함 「시험」, 휴대폰 `010-0000-0000`).
- 화면 맨 위에 띠를 둔다: 「시험용 화면입니다. 실제 문의로 접수되지 않으며, 입력한 내용은 시험 기록으로 저장됩니다.」
- 위저드는 공개본과 같은 컴포넌트를 쓰고, **항상 `test: true`로 보낸다.**
  - 접수번호는 `T-`로 시작한다.
  - 수신 측은 시험 접수를 운영 상담 목록과 알림으로 보내지 않는다.
  - 시험이 끝나면 시험 기록은 사람이 지운다.
- **의견 칸**:
  - 미리보기에서만 질문 화면마다 「이 질문에 대한 의견」 칸(선택, 300자)을 두고, 마지막에 「전체 의견」 칸(1000자)을 둔다.
  - 의견은 시험 접수의 `inquiry.answers`에 `{q: "[의견] S5 인원", a: "…"}`로 함께 실린다. 그래서 어떤 답을 고른 상태에서 나온 의견인지 같이 남는다.
  - 의견을 모두 합쳐 5000자를 넘으면 제출 전에 알려 준다(잘라 보내지 않는다).
  - 끝까지 가지 않아도 의견을 남길 수 있게, 어느 화면에서든 [의견 복사] 버튼을 둔다(카톡으로 보내는 길).
  - 중계(n8n)가 아직 없으면 보내지 않는 시험 모드로 동작한다. 완료 화면에 보낼 내용을 보여 주고 [의견 복사]를 둔다.

**같은 사이트의 숨은 주소로 하는 이유**

- 중계는 `https://hyedu.kr`을 출처로 허용한다(CORS). 별도 도메인에 시험 사이트를 띄우면 중계 설정까지 바꿔야 한다.
- GitHub Pages는 브랜치 하나만 배포한다. 브랜치별 미리보기 주소를 만들려면 호스팅을 하나 더 세워야 한다.
- 지금 `/contact`를 건드리지 않으므로 main에 올려도 고객이 보는 화면은 그대로다.

**처리방침 페이지**

- `/privacy`는 미리보기 기간에 「초안」 띠와 `noindex`를 달고, Footer · 사이트맵에 넣지 않는다.
- 데이터 파일의 상수 하나로 초안 상태를 켜고 끈다.

**시험하는 분께 드릴 목록** (주소를 직접 드린다)

1. `/ko/contact/preview/?program=autonomous-driving`: 초등학교 · 체험교실 · 프로그램이 미리 채워진 상태로 시작
2. `/ko/contact/preview/`: 고등학교 · 동아리 10회기 · 예산 총액
3. 같은 주소: 학교 축제 · 체험부스 · 부스 조건 일부만 채우기
4. 같은 주소: 자녀 개인 참가 분기
5. 같은 주소, 휴대폰으로: 거의 모든 질문을 「모르겠어요」로 넘기고 연락처만 넣기

**개발 쪽 확인 목록** (시험하는 분께 맡기지 않는다)

- `/en/contact/preview/`: 영어 화면, 보내는 값은 한국어인지
- 입력 오류: 휴대폰 형식, 이메일 회신인데 이메일 없음, 동의 안 함
- 400 · 500 · 시간 초과 · 이상한 응답에서 입력이 보존되는지, 결과 불명 뒤 수정하면 새 번호가 되는지
- 임시 저장: 7일 만료, 공개본과 미리보기 키 분리, 연락처 · 자유 입력이 저장되지 않는지
- 360 · 390 · 768px

**공개(커트오버)**

1. 의견 반영 → 다시 시험
2. `/contact`를 위저드로 바꾼다. 처리방침의 초안 상태를 끄고, Footer · 사이트맵에 처리방침을 넣는다.
3. 프로그램 상세 페이지의 신청 버튼에 `?program=<slug>`, 서비스 목록 페이지 버튼에 `?type=`을 붙인다.

5. 공개 시각을 수신 측에 알려 그 시각부터 운영 목록에 올리게 한다.
6. 미리보기 경로는 나중에 질문을 고칠 때 다시 쓰도록 남겨 둔다.
